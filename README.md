# Практична робота: Ознайомлення з fetch api

**Тема:** Ознайомлення з fetch api  
**Мета:** Ознайомитися з призначенням fetch api, навчитися виконувати HTTP-запити GET, POST, PUT і DELETE до серверного сервісу з коду JavaScript, опрацьовувати відповіді асинхронно за допомогою промісів та async/await, відокремлювати завантаження даних від оновлення вмісту сторінки, а також будувати таблицю з отриманих даних, використовуючи метадані з власних атрибутів заголовка таблиці.

---

## Опис виконаної роботи

1. Створено веб-сторінку `index.html` із розміткою таблиці `<thead id="table-header">`, де кожна колонка містить власний атрибут `x-column` із зазначенням імені поля серверної моделі, та елемент `<p id="status">` для виведення статусу запитів.
2. У файлі `app.js` реалізовано:
   - асинхронну функцію `loadData()` для відправки GET-запиту за допомогою `fetch()`;
   - функцію `renderTable(data)` для генерації рядків на основі метаданих `x-column`;
   - функцію `createCell(fieldName, model)` для формування окремих `<td>`;
   - функцію `refresh()`, яка окремо координує завантаження та виклик рендерингу;
   - набір методів `createPosting()`, `updatePosting()`, `deletePosting()` для виконання POST, PUT та DELETE операцій.
3. Підготовлено файл `requests.rest` для тестування ендпойнтів сервісу.

---

## Відповіді на контрольні запитання

### 1. Що таке fetch api і для чого він використовується?
**Відповідь:**  
Fetch API — це сучасний браузерний механізм для виконання асинхронних мережевих HTTP-запитів до сервера. Він використовується для завантаження, додавання, редагування та видалення даних без потреби перезавантажувати всю веб-сторінку.

---

### 2. Чим асинхронний виклик відрізняється від синхронного? Чому мережеві запити виконуються асинхронно?
**Відповідь:**  
Синхронний виклик повністю заморожує виконання програми та інтерфейс користувача до моменту завершення операції. Асинхронний виклик відправляє запит у фоновому режимі, дозволяючи браузеру миттєво продовжувати взаємодію з користувачем. Оскільки швидкість мережі та відповіді сервера непередбачувана, запити роблять асинхронними, щоб уникнути підвисання сторінки.

---

### 3. Що таке Promise? У яких станах він може перебувати?
**Відповідь:**  
Promise — це об'єкт у JavaScript, який зберігає майбутній стан та результат асинхронної операції.  
Він може бути в 3 станах:
1. Pending (очікування);
2. Fulfilled (успішно виконано);
3. Rejected (відхилено через помилку).

---

### 4. Як опрацювати результат проміса за допомогою then() і catch()? Як це зробити за допомогою async/await?
**Відповідь:**  
- Через методи `then()` і `catch()`: викликається ланцюжок `.then(response => response.json()).then(data => ...).catch(err => ...)`.
- Через синтаксис `async/await`: функція позначається словом `async`, виклик проміса очікується через `await`, а помилки перехоплюються конструкцією `try/catch`.

---

### 5. Як за допомогою fetch() виконати запити GET, POST, PUT і DELETE? Які налаштування потрібні в кожному випадку?
**Відповідь:**  
- **GET:** стандартний виклик `fetch(url)` без другого параметра.
- **POST:** передається об'єкт конфігурації `{ method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(data) }`.
- **PUT:** адреса містить ідентифікатор (`url + '/' + id`), метод `'PUT'`, заголовок `Content-Type: application/json` та тіло `body`.
- **DELETE:** адреса містить ідентифікатор (`url + '/' + id`), метод `{ method: 'DELETE' }`, тіло відсутнє.

---

### 6. Чому логіку завантаження даних із сервера варто відокремлювати від логіки оновлення вмісту сторінки?
**Відповідь:**  
Це розділяє обов'язки в коді (архітектурний принцип):
1. Завантаження `loadData` відповідає лише за роботу з мережею, а `renderTable` — лише за відображення DOM.
2. При зміні структури HTML не потрібно переписувати мережевий код.
3. Функцію `renderTable` можна окремо тестувати на локальних масивах.
4. Після модифікації даних (POST/DELETE) можна повторно викликати одну функцію `refresh()`.
